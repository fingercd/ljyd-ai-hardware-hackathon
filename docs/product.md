# 奶龙盯盯：产品与交互方案

**工作名：奶龙盯盯 / Study Dino。** 定位、交互和感知方案属于设计，尚无实物功能验收。本文不声明识别准确率或学习效率提升。

## 核心定位

**把用户自己定下的学习约定，变成桌边可感知的提醒。**

第一批场景是成年用户独自在书桌学习、备考或读书，并主动选择接受监督。目标不是监督所有人、判断努力程度或替家长控制孩子，而是帮助本人发现自己何时偏离了先前的约定。

角色反差是作品记忆点：外表软萌，查岗认真；语气有点欠，规则要讲理。主标语为「长得像来陪读的，其实是来抓摸鱼的。」

## 三层价值

1. **看得见的互动**：把屏幕通知变成语音、震动和少量水花，形成一次有记忆点的桌面反馈。
2. **说得清的提醒**：Agent 对照当前学习／休息约定解释为什么询问，不把姿势、离场或看手机直接等同于心理分心。
3. **收得住的边界**：本人同意、模式清楚、可以暂停、动作有限，断网和未知状态下不追加物理动作。

这些是产品设计主张，不是已验证学习效果。喷水是互动特征，不能成为物理惩罚或危险装置。

## 从主办方路线走向原型

用户转述的推荐顺序为：**交互创建 → 调试预览 → 标准设备接入 → 个性化开发**。当前采纳此顺序。

- 先在平台建立角色、学习约定、模式与失败回答，用明确标记的测试事件调试。
- 再接标准开发板，验证云端身份、联网、语音与恢复。
- 最后接入真实感知事件，并对震动和喷水分别做电气与功能验收。
- SDK 构建是准备和排障工具，不以底层大改替代产品交互验证。

## 感知范围先收小

首版候选：电脑侧本地摄像头观察**单人、预设学习区的在场／持续离场**。电脑是明确展示的组成部分，不冒充全部算法已在 ESP32-S3 上运行。

持续离场只是一个候选行为事件。用户可能在拿书、合理休息或处理事情；低头可能在读书。具体阈值、是否加入手机检测、摄像头模型和实际部署位置，都需要后续选择与测试。

视频本地处理、默认不上传原始视频是设计目标；必须以实际数据流验证后才能宣传已经实现。云端语音链路也不能被描述为完全离线。

## 提醒模式与水路

| 模式设计 | 目标体验 | 边界 |
|---|---|---|
| 陪读 | 语音询问与提醒 | 不启动执行器 |
| 认真一点 | 语音＋短时震动 | 会话开始时主动选择，可立即暂停 |
| 来点水花 | 语音＋震动＋受控喷水 | 喷水单独同意，固定独立接水区、默认关闭 |

动作由确定性规则约束，不能让模型随意决定持续时间、重复次数或目标。一次触发的安全上限、冷却间隔和供电规格由硬件验证确定，不在未看板型时编造数值。

水路设计需满足：低压低量、方向固定、避开脸部与身体敏感部位、远离电子和市电、接水容器、防溅、匹配驱动与独立供电路径、物理硬停用。阀泵等硬件尚未选型，不提供猜测针脚。

初次演示先分别验证震动与水路。即使最终模式组合触发，也不能跳过单独验收。按下停用或状态不明时，保持不喷水；不能将「未收到失败」理解为成功。

## Agent 的职责

- 理解当前约定和用户解释，决定如何询问、提醒、暂停及总结。
- 将需要动作的意图交给受限执行层；执行层做权限、模式、参数、速率和设备状态校验。
- 区分请求已提出、已发送、设备收到、输出结束与物理结果。没有传感器确认实际出水时，需人工观察，不能拿消息回执当作物理证据。
- 用户要求停止的优先级高于角色吐槽。模型、知识库和网页内容不能扩大设备权限。

具体工具接入与平台 API 仍待实际核验。事件文案和提示词不等于已存在的平台协议。

## 不包装成什么

不宣称脑机接口、医疗专注力诊断、读心、通用具身智能平台或首创摄像头督学。没有对照数据前不写「提升多少效率」「准确率多少」「防止所有摸鱼」。

差异化放在**自主约定＋角色化解释＋可中止的实体反馈体验**。这既能在现场看见，也能通过失败场景检验。
