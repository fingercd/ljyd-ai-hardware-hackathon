# 路演与 Demo 脚本

本页为设计脚本，**当前没有已经通过验收的完整实物 Demo**。脚本中的实时识别、动作与回执，只有实际完成后才能在现场称为实时功能。

## 15 秒介绍

> 把奶龙放上书桌，本来想找人陪读，结果像给自己请了个监考员。我们正在做「奶龙盯盯」：按你自己定下的学习约定，观察可见行为线索，先用语音问清楚，再用震动和受控水花提醒你回来。它可以有点欠，但监督始终由你决定。

这段是概念介绍，不需要假装已有识别效果。

## 75 秒目标演示

| 时间 | 给观众看什么 | 要证明什么 |
|---|---|---|
| 0–10 秒 | 一个人打开书，却顺手拿起手机的短场景 | 一个清晰、熟悉的问题，不铺宏大行业叙事 |
| 10–22 秒 | 用户和奶龙约定本次学习／休息与提醒模式 | 监督是用户主动选择，角色有互动 |
| 22–42 秒 | 摄像头观察约定区域的事件，界面显示来源和时间；奶龙询问 | 感知范围有限、理由可解释，不冒充读心 |
| 42–56 秒 | 授权模式下短时震动，独立接水区少量水花，展示实际输出 | 这是实物闭环，不是只发一条消息 |
| 56–66 秒 | 用户说「我在休息」或按硬停用，动作停止/不触发 | 讲理、可中止，失败边界有设计 |
| 66–75 秒 | 一张小架构图＋已完成/未完成表 | 观众知道设备、电脑、平台各做什么 |

实际设备未达到此范围时，缩小演示，而不是照稿假演。

## 五个必测场景

1. **正常候选事件**：在已同意的模式下发生持续离场等目标事件，奶龙询问，执行链记录与现场动作对应。
2. **低头读书**：不能仅因姿势或暂时低头就断定不认真，更不能直接触发喷水。
3. **合理休息**：明确休息或暂停后，监督和执行器按模式停止，不连续骚扰。
4. **遮挡、断网或无回执**：显示「未知／无法判断／设备未确认」，不补猜，不自动追加动作。
5. **撤销、重复事件和硬停用**：撤销后不执行；同一事件不导致危险重复；硬停用能独立于云端约束执行器。

## 透明降级

- 视觉未通：用同类测试事件或按钮注入，画面持续显示「人工触发，非 AI 识别」，只能证明后半段交互。
- 标准设备未通：先展示平台预览，把硬件演示分开，不称为端到端。
- 水路未过安全验收：可以展示模式选择和拒绝执行，或只演示已验证震动；明确喷水尚未启用。
- 概念动画、分镜和故事板必须标「概念」，不用它们冒充实测视频。

## 评委追问的诚实回答

**怎么知道我没有认真学？** 首版拟检测的是约定区域的可见行为事件，不是内在注意力；事件需要结合学习/休息约定和用户解释，复杂检测尚待验证。

**为什么需要 Agent？** 目标是在当前约定和解释下进行有角色的询问、提醒与暂停，而不是只报一个阈值；物理动作仍由确定性规则约束。

**喷水是不是噱头？** 它是作品的互动记忆点，但不是全部价值；主要闭环是自定约定、可解释提醒和可核验反馈。设计要求是水路独立、低量并有硬停用，均需实物验证；安全门未过就不启用。

**是不是已经证明能提升学习效率？** 没有。可先报告任务、误报、停止成功、设备回执和真实演示；学习效果需要之后有设计的验证。

## 三分钟正式展示的建议结构

75秒是核心交互段。按已保存赛题的3分钟展示要求，可用：0–25秒问题与奶龙反差；25–110秒串起查岗与休息/复归两条流程；110–145秒解释指定摄像头、三类可见状态、平台调用和设备反馈；145–170秒演示误判/离线/停止边界；170–180秒收束真实完成范围与价值。具体节奏以实际彩排计时调整。

电脑视觉或人工事件只用于早期预演，不能作为完成指定摄像头与三类坐姿要求的证明。完整交付见 [对齐清单](challenge-checklist.md)。
