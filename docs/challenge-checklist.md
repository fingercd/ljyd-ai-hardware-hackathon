## 必须保留的目标

| 已保存要求 | 奶龙方案如何对应 | 当前状态 |
|---|---|---|
| 指定核心板及配件、SPI 摄像头、语音、灵机一动平台 | 标准设备接入后再定制奶龙；电脑摄像头只作前期预演 | 实物及最终链路待确认 |
| 至少两条相关可运行工作流 | 学习状态查岗＋主动休息/暂停/复归，共享学习上下文 | 仅方案 |
| 摄像头坐姿识别，至少三类使用情况 | 拟采用在座符合约定、持续偏离约定、离座；未知另列 | 分类与平台返回待验证 |
| 至少两种硬件反馈 | 目标包含震动、受控喷水及语音；先逐项验收 | 尚未实板验证 |
| 连续至少两轮语音 | 立约→解释/休息→复归，需真正对话与状态关联 | 待设备接入 |
| 平台能力真实调用 | 工作流/场景/知识库等至少一项能力，保留触发、输入、输出及硬件结果 | 尚未调用 |
| 可重复端到端运行与异常处理 | 相同任务可重复，支持未知、离线、撤销和恢复 | 待验收 |

标签和工作流是设计建议，不代表平台已经支持或本项目已经达标。不能把“在线”、人工触发或模板预览当作最终真实能力。

## 最终交付准备

- [ ] 真实可运行作品和重复演示记录。
- [ ] 可编译工程、README、平台配置导出或官方认可的配置留档。
- [ ] 第三方组件与素材来源声明。
- [ ] 正式交付验收后创建 `hackathon-final` Git 标签；不提前给未完成版本贴最终标签。
- [ ] 0.8 m × 1.8 m 展示海报。
- [ ] 3 分钟路演/演示；75 秒脚本只是其中的重点演示段，不替代全部要求。
- [ ] 一页方案说明。
- [ ] 至少一次平台调用的触发条件、输入、结果及实际硬件反馈证据。
- [ ] 接线、配网、演示准备和异常恢复说明。
